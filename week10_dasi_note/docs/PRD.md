## 1. 사용자와 사용 상황

- 앱 이름: 다시노트 (한 줄 소개: 다시 볼 것만 모아두는 노트)
- 주제 한 문장: 시험 오답, 헷갈리는 개념, 실수, 읽을거리처럼 나중에 다시 볼 것을 노트북별로 한곳에 모으고, 다시 볼 것만 골라 볼 수 있게 돕는 웹앱
- 첫 사용자: 나 자신(시험 준비를 하는 학생, 2027년 1분기 자격증 응시 목표). 앱 구조는 시험 준비에 한정하지 않고 다시 볼 것을 모으려는 누구나 쓸 수 있게 한다. 시험 준비 외의 사용자는 아직 확인하지 않았다(2장 가정 참고).
- 사용하는 순간: 틀리거나 헷갈린 직후, 또는 나중에 읽으려고 남겨 두고 싶을 때 항목을 기록하고, 다시 볼 시점(시험 직전 포함)에 다시 볼 것만 골라 확인할 때
- 용어 원칙: 앱 전체 문구는 중립으로 쓴다(다시 볼 것, 노트북, 항목, 완료). 구체적인 용어(문제 요약, 틀린 이유 등)는 템플릿 안에서만 쓴다. 구조는 범용으로, 첫인상은 구체적으로 한다.

## 2. 문제·사실·가정

- 문제 한 문장: 다시 볼 것을 따로 모아 두지 않으면, 필요한 순간에 다시 볼 자료가 없다.

| 구분 | 내용 | 근거·한계 또는 확인 방법 |
| --- | --- | --- |
| 확인한 사실 | 나는 현재 틀린 문제를 따로 기록하지 않고 있다. 학교 시험을 보기 몇 분 전에 다시 볼 오답이 없어 불편했다. | 본인 경험 한 사례(2026년 11월 3일 기준 진술)이며 다른 사람 전체에 해당하는 근거는 아님. 어떤 과목이었는지, 정확한 시점은 [추가 확인 후 기입] |
| 문제에 관한 가정 | 시험 오답뿐 아니라 헷갈린 개념, 실수, 읽을거리도 다른 사람이 따로 모아 두지 못해 다시 볼 때 불편할 것이다 | 확인한 사실은 시험 오답 한 사례뿐이고 나머지는 추측이다. 대상과 빈도는 미확인. 서로 다른 상황의 지인 2~3명에게 "다시 보려고 남겨 두는 것이 있나요? 어디에 어떻게 두나요?"라고 물어 확인 |
| 해결 효과의 가정 | 다시 볼 것을 노트북별로 한곳에 모으면 다시 볼 때 누락이 줄 것이다 | 앱을 직접 사용해 항목을 쌓은 뒤, 다시 볼 시점에 쓸 수 있었는지로 확인 |
| 활용 범위의 가정 | 노트북 템플릿(시험 오답, 개념·용어, 실수·회고, 읽을거리, 직접 만들기)이 있으면 사용 목적과 상관없이 쓸 수 있을 것이다 | 서로 다른 목적의 2명에게 실제로 노트북을 만들고 항목을 적어 보게 하고 막힌 지점을 기록. 템플릿 종류와 레이블이 적절한지도 이때 확인 |
| 위험 요소(가정) | 앱을 열어 적는 과정이 번거로우면 기록하지 않게 될 수 있다. 지금 기록하지 않는 이유도 이것일 수 있으나 아직 확인하지 않았다. | 입력을 최소화한 화면(R3, AC9)으로 일주일 동안 직접 쓰고, 기록하고 싶었던 횟수 대비 실제로 기록한 횟수를 센다 |

AI가 만든 수치와 예시를 조사 사실로 적지 않습니다. 본인의 경험도 다른 사용자 전체에 해당하는 사실로 확대하지 않습니다.

## 3. 핵심 가치

- 사용자가 얻을 결과: 다시 볼 것이 여기저기 흩어져 필요할 때 찾지 못하는 상태 → 노트북별로 모인 항목 중 다시 볼 것만 골라 볼 수 있는 상태
- 기능과의 연결: 다시 볼 것을 바로 기록하고(항목 추가, 노트북은 템플릿으로 만듦) 노트북별로 걸러 보고(필터) 다시 볼 것만 본다(다시 볼 것만 보기). 다시 본 것은 완료로 표시한다.

## 4. 기능과 이번 구현 범위

- 앱 전체의 핵심 기능 후보: 항목 추가(노트북 만들기 포함), 노트북 템플릿, 항목 목록, 노트북별 필터, 다시 볼 것만 보기, 완료 표시, 항목 수정·삭제, 노트북 이름 수정·삭제, 노트북별 통계, 시험 D-day 표시(시험 오답 노트북용)
- 오늘 구현할 첫 화면과 행동: 다시 볼 것 화면(요약 카드 + 다시 볼 것만 보기 + 항목 목록 + 추가 버튼), 처음 사용 온보딩(템플릿 카드로 노트북 만들기), 새 노트북 만들기, 항목 추가와 저장, 완료 표시
- 후속 작업으로 남길 기능과 이유 (우선순위 순):
  1. 로컬 저장(브라우저에 저장): 다른 사람이 쓰려면 앱을 껐다 켜도 데이터가 남아야 하므로 첫 화면 확인 직후 가장 먼저 한다. 이번 수업 범위(첫 화면 확인)에서는 제외한다
  2. 항목 수정·삭제, 노트북 이름 수정·삭제: 노트북을 지울 때 그 노트북의 항목을 어떻게 할지 정해야 해서 범위가 커진다
  3. 통계·D-day, 복습 모드: 데이터가 쌓여야 의미가 있고 통계는 SQL 집계를 배운 뒤 DB와 함께 구현한다
  4. 이미지 업로드: 저장소 연동이 필요하여 이후로 미룬다
  5. 로그인·서버 저장, 서버 배포(리눅스·AWS): 앱이 동작하고 로컬 저장이 끝난 뒤 진행한다. 로그인이 없는 동안 데이터는 각자의 브라우저에만 저장된다
- 데이터 출처: 사용자 입력만 사용한다. 개발 중 화면 확인용 예시 데이터는 코드에 둘 수 있으나 첫 실행 화면에는 나오지 않게 한다("예시 보기" 버튼을 눌렀을 때만 채운다). 외부 자료 연동 없음
- 저장·외부 연동의 현재 범위: 메모리에만 저장(앱을 다시 실행하면 초기화됨). 로컬 저장·DB 저장과 외부 연동은 미구현
- 화면 구조와 반응형: 웹앱 관리 화면(SB Admin 스타일)처럼 맨 위 상단바와 왼쪽 사이드바를 두고, 본문에 요약 카드와 항목 목록을 보여 준다. 앱은 하나로 만들고 화면 너비에 따라 배치만 바꾼다. 너비 800px 이상에서는 사이드바가 펼쳐져 있고 입력 팝업이 화면 가운데 모달로 뜬다. 800px 미만에서는 사이드바가 접혀 있다가 상단바의 ☰ 버튼으로 열고, 입력 팝업은 아래에서 올라온다. 사이드바는 밝은 색(Light Sidenav)으로 하고 어두운 테마는 쓰지 않는다.
- 사이드바 메뉴 구성: "다시 볼 것"(이번 구현), "복습 모드"·"통계"(후속 작업이라 흐리게 표시하고 "준비 중"으로 둔다), 노트북 목록(전체 + 내가 만든 노트북)과 "새 노트북"은 같은 사이드바에 둔다. 메뉴 이름은 가칭이다.
- 노트북과 템플릿: 노트북은 템플릿을 하나 가진다. 템플릿은 입력 칸의 이름(레이블)과 예시 문구, 항목 줄에 보이는 메모 이름만 바꾸고 구조는 모두 같다. 항목은 제목(필수), 메모(선택), 추가한 날짜로 이루어진다.

| 템플릿 | 이름 기본값 | 제목 레이블 | 메모 레이블 |
| --- | --- | --- | --- |
| 시험 오답 | 시험 오답 | 문제 요약 | 틀린 이유 |
| 개념·용어 | 개념·용어 | 용어 | 헷갈린 점 |
| 실수·회고 | 실수·회고 | 상황 | 다음엔 이렇게 |
| 읽을거리 | 읽을거리 | 제목 | 저장한 이유 |
| 직접 만들기 | (사용자 입력) | 제목 | 메모 |

- 용어 정리(PRD·화면·코드 공통): subject → notebook(노트북), question → title(제목), reason → memo(메모). 항목에 createdAt(추가한 날짜)을 둔다. 완료 상태 이름은 "다시 볼 것"(아직 안 본 것)과 "완료"로 쓴다.

## 5. 첫 화면

| 요구 번호 | 사용자가 볼 정보 | 입력·선택·버튼 | 행동 후 반응 |
| --- | --- | --- | --- |
| R1 | 상단바(앱 제목, 한 줄 소개(PC), ☰ 버튼, "전체 완료 x / y" 점수), 사이드바(메뉴, 노트북 목록: 전체 + 내가 만든 노트북), 요약 카드(전체·다시 볼 것·완료), 항목 목록(노트북, 추가한 날짜, 제목, 메모, 완료 여부) | ☰ 버튼(폰에서 사이드바 열기·닫기), 준비 중 메뉴(복습 모드·통계) 누르기 | 항목이 있으면 최신순으로 표시된다. 노트북이 하나도 없으면 처음 사용 화면(R5)이 보인다. 노트북은 있는데 항목이 없으면 "이 노트북에는 아직 항목이 없어요" 안내가 보인다 |
| R2 | 사이드바의 노트북 목록, "다시 볼 것만 보기 (N)" 토글(N은 현재 노트북에서 완료하지 않은 항목 수) | 사이드바에서 노트북 선택, 다시 볼 것만 보기 선택·해제 | 선택한 노트북의 항목만 목록에 보이고 요약 카드 숫자도 그 노트북 기준으로 바뀐다. 다시 볼 것만 보기를 켜면 완료한 항목은 숨는다. 켠 상태에서 방금 완료로 바꾼 항목은 노트북이나 토글을 바꾸기 전까지 그 자리에 남아 되돌릴 수 있다 |
| R3 | 항목 추가 입력 영역(팝업). 선택한 노트북의 템플릿에 맞는 제목·메모 이름과 예시 문구, 제목 칸 아래 힌트(예: 시험 오답 "문제 번호나 핵심 단어만 적어도 돼요") | 노트북 선택(내 노트북 칩, 마지막에 고른 값 유지), 제목 입력(필수, 한 줄), 메모 입력(선택), 저장 버튼(가장 강조), 저장하고 계속 버튼, 닫기 | 저장하면 목록 맨 위에 새 항목이 추가된다. 저장하고 계속을 누르면 팝업이 열린 채 제목·메모 칸만 비워지고 노트북은 유지된다. 팝업에서 노트북을 바꾸면 입력 칸 이름이 즉시 그 템플릿의 이름으로 바뀐다 |
| R4 | 항목의 완료 상태("다시 볼 것" 또는 "완료") | 항목의 상태 버튼(체크 표시, 다시 누르면 취소) | 누를 때마다 완료/다시 볼 것이 바뀌어 상단 점수와 요약 카드 숫자도 함께 바뀐다. 버튼의 접근성 이름은 누르면 일어나는 동작("완료로 표시", "다시 볼 것으로 표시")으로 한다 |
| R5 | 처음 사용 화면(노트북이 0개일 때 항목 목록 자리에 보임): 제목 "무엇을 모아볼까요?", 부제 "오답, 헷갈리는 개념, 실수, 읽을거리까지. 나중에 다시 볼 것을 모아 두세요.", 템플릿 카드 4개(2열, 폰에서도 2열; 카드마다 아이콘, 템플릿 이름, 필드 안내 한 줄) | 템플릿 카드 선택, "직접 만들기(빈 노트)", "예시 보기" | 카드를 누르면 그 템플릿의 이름으로 노트북이 자동으로 만들어지고 곧바로 첫 항목 입력 팝업이 열린다(이름 짓기 생략). "직접 만들기"는 새 노트북 팝업을 직접 만들기 템플릿으로 연다. "예시 보기"는 예시 데이터를 채운다. 노트북이 생기면 이 화면은 사라진다 |
| R6 | 새 노트북 팝업: 템플릿 선택 칩(5종), 선택한 템플릿의 항목 구성 안내, 노트북 이름 칸(템플릿 이름이 기본값) | 템플릿 선택, 이름 수정, 저장, 닫기 | 저장하면 노트북이 사이드바에 생기고 그 노트북이 선택된다. 처음 사용 화면이나 노트북이 없을 때 추가 버튼으로 연 경우에는 저장 직후 첫 항목 입력 팝업이 이어서 열린다 |

```

```

- 폰 배치(800px 미만)는 사이드바가 접히고, 상단바의 ☰ 버튼을 누르면 사이드바가 열린다. 노트북을 고르거나 바깥을 누르면 닫힌다.
- 요약 카드의 숫자는 사용자가 입력한 항목에서 계산한다(전체, 다시 볼 것, 완료). 선택한 노트북 기준으로 바뀐다. 위 숫자는 화면 구상용 예시다.
- 상단바 오른쪽의 "전체 완료 x / y"는 선택한 노트북과 관계없이 모든 노트북을 합친 기준이다. 이 범위가 드러나도록 "전체"를 붙이고, 마우스를 올리면 설명이 보인다.
- 이번 구현에서 사이드바 메뉴 중 실제로 동작하는 것은 "다시 볼 것"과 노트북 목록, "새 노트북"이다.
- 시각 요소: 사이드바와 템플릿 카드의 아이콘, 완료 체크는 그림(SVG)으로 그린다. 비활성 메뉴는 체크 모양으로 보이지 않게 구분한다. 마우스가 있는 환경에서는 메뉴·버튼에 마우스를 올렸을 때 표시가 바뀐다. 본문 글씨는 12px 이상(가능하면 13px 이상)으로 한다.

빈 데이터나 잘못된 입력 등 해당하는 조건:
- 노트북이 하나도 없으면 처음 사용 화면(R5)을 보여 준다. 이때 추가 버튼을 누르면 새 노트북 팝업이 먼저 열린다.
- 노트북은 있는데 항목이 하나도 없으면(전체 보기, 또는 선택한 노트북) "이 노트북에는 아직 항목이 없어요. '추가'를 눌러 첫 항목을 넣어 보세요." 안내를 보여 준다.
- 제목이 비어 있으면 저장하지 않고 "{제목 레이블}을(를) 입력해 주세요"(예: "문제 요약을 입력해 주세요", "용어를 입력해 주세요") 안내를 보여 주며 입력한 다른 값은 유지한다.
- 새 노트북 이름이 비어 있으면 "노트북 이름을 입력해 주세요", 이미 있는 이름이면 "이미 있는 노트북이에요"라고 안내하고 저장하지 않는다. 이름은 앞뒤 공백을 지우고 20자까지 허용한다. 이름 칸에는 템플릿 이름이 기본값으로 들어가고(같은 이름이 이미 있으면 뒤에 번호를 붙인다) 고칠 수 있다.
- 지금 보고 있는 노트북과 다른 노트북으로 항목을 저장하면, 저장한 노트북으로 이동해 새 항목이 바로 보이게 한다. 추가 팝업을 열면 지금 보고 있는 노트북이 미리 선택되어 있다.
- 메모는 선택 입력이다. 비워도 저장할 수 있고 항목에는 메모 줄을 표시하지 않는다. (입력 부담을 줄여 기록이 쌓이게 하려는 결정)
- 노트북이 많아져 사이드바가 화면 높이를 넘으면 사이드바 안에서 세로로 스크롤할 수 있다.

확인할 질문·미정:
- 결정함: 메모는 선택 입력, 완료는 취소 가능 (입력 부담을 줄이고 실수로 누른 경우를 되돌리기 위해)
- 결정함: 노트북은 새 노트북 팝업(또는 처음 사용 카드)에서만 만든다. 노트북 이름 수정·삭제는 후속 작업 (범위를 줄이기 위해)
- 결정함: 앱 전체 문구는 중립으로, 구체적인 용어는 템플릿 안에서만 쓴다
- 미정: 템플릿 5종과 레이블이 실제 사용자에게 맞는지 (활용 범위 가정을 확인할 때 같이 본다)
- 미정: 노트북 삭제 시 그 노트북의 항목을 함께 지울지, 다른 노트북으로 옮길지
- 미정: 항목에 날짜 외에 "중요 표시"를 달 필요가 있는지
- 시험 정확한 날짜 미정 (2027년 1분기 목표)
- 앱 이름 "다시노트"는 가칭이다. 같은 이름의 기존 앱이 있는지는 아직 확인하지 않았다.

피드백과 수정 이유:
