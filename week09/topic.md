# 9주차 최종 주제 정리 (한 장)

> **상태: 검토안 — 교수님 미확인** (확정·조건부 확정·재선정 필요 중 어느 것도 아직 받지 않음)
> 상세 근거는 `week09/analysis.md` 참고. 정적 분석: 해당 없음 — 기획 문서만 변경.

## 1. 주제와 선택 이유

| 항목 | 내용 |
| --- | --- |
| 주제 (가칭) | 약속 시각 기록 — 내가 정한 시각과 실제 시각의 차이를 확인하는 앱 |
| 변경 여부 | 7주차 주제(오답노트)에서 변경 |
| 선택 이유 | 직접 겪는 문제이고 숫자로 확인할 수 있음 (취침 2~3시 넘김, 주말 알바 2~3분 지각) |
| 변경 이유 | 오답노트는 직접 겪은 불편이 아니고 대체할 수 있는 앱이 많다고 본인이 판단 |

## 2. 사용자·상황·문제

- **사용자**: 수업과 주말 알바를 병행하는 대학생(본인)
- **상황**: 밤에 보상심리로 폰을 오래 보다 늦게 잠 / 주말 알바(17:00) 출근 준비
- **문제**: 정한 시각을 자주 어기지만 얼마나 어긋나는지 기록하지 않아 개선 여부를 모름

| 구분 | 내용 |
| --- | --- |
| 사실 (본인 경험) | 밤 2~3시가 넘도록 자는 날이 많음 / 주말 알바에 2~3분 지각이 습관 / 기상 알람은 요일별로 고정 |
| 가정 (미확인) | 알림과 기록이 어긋남을 줄인다 / 지각 원인은 알람 후 미룸 또는 준비 시간 부족 |
| 연결하지 않음 | 수면 부족과 알바 지각의 인과 (알바가 17시 출근이라 근거 약함) |

**조사 근거**: 본인 경험만 있음. 유사 앱 조사와 다른 사용자 확인은 **아직 안 함** (`analysis.md` 3절 빈 표).

## 3. 핵심 흐름 (MVP)

1. 요일별 기상 알람 시각과 알바 출근 시각을 설정한다 (처음 한 번).
2. 앱이 내일 기상 알람 기준으로 **권장 취침 시각**을 계산해 보여 준다.
3. 실제 취침·기상·출근 도착 시각을 입력한다.
4. 목표 시각과의 **차이(분)** 가 바로 표시되고 최근 기록에 쌓인다.

## 4. 범위 (MoSCoW)

| 분류 | 기능 | 이유 |
| --- | --- | --- |
| Must | 요일별 기상 알람·출근 시각 설정, 목표 수면 시간(7~8시간) 설정 | 권장 시각 계산의 입력 |
| Must | 권장 취침 시각 계산 + 시각 알림 | 문제의 출발점 |
| Must | 실제 시각 기록 → 차이(분) 계산 | 개선 여부를 숫자로 확인 |
| Should | 기상 시각 기록(미룸 확인), 수면 시간 표시 | 지각 원인 구분 |
| Should | 늦게 잔 이유 선택, "10분 뒤 다시" 알림, 최근 7일 목록 | 동기 확인·비교 |
| Could | 취침 시각 상한 설정, 취침과 지각의 연결 요약 | 기록이 쌓인 뒤 판단 |
| Won't this time | 앱 사용 감지·차단, 건강 앱 연동, 로그인, 친구 비교, 학교 지각 기록, 시간표 연동 | 권한·외부 의존 / 근거 없음 |

Must끼리의 의존: 요일별 설정 → 권장 취침 계산 → 알림, 실제 시각 기록 → 차이 계산.
Must가 4개라 10주차 전에 줄일 수 있는지 다시 검토함 (`analysis.md` 6절).

## 5. 화면 스케치 (두 화면)

**홈 화면**

```
┌────────────────────────────────┐
│ 오늘 (월) 11/16        [설정]  │
│ 내일 기상 알람  08:23          │
│ 오늘 밤 권장 취침  00:23~01:23 │
│ (수면 7~8시간 기준)            │
│                                │
│ [ 지금 잠 ]  [ 직접 시각 입력 ]│
│ → "+77분 늦음" (입력 뒤 표시)  │
│                                │
│ 최근 7일                       │
│ 11/15 취침 목표 01:23 실제 02:40 +77분 │
│ 11/15 출근 목표 17:00 실제 17:03 +3분  │
│ (기록 없음일 때: "아직 기록이 없어요") │
└────────────────────────────────┘
```

**설정 화면**: 요일(월~일)별 기상 알람 시각(없음 허용), 알바 요일의 출근 시각, 목표 수면 시간.

숫자는 예시이며 실제 기록이 아님.

## 6. 데이터·저장·외부 의존

| 필드 | 자료형 | 규칙 |
| --- | --- | --- |
| 요일 설정: 요일, 기상 알람 시각(비어도 됨), 출근 시각(비어도 됨) | enum, time | 수요일은 알람 없음 |
| 목표 수면 시간 | 분 | 420~480, 직접 설정 |
| 기록: 날짜, 종류(취침/기상/출근), 목표 시각, 실제 시각 | date, enum, time | 실제 시각은 입력 필수 |
| 차이(분) | 계산값 | 저장하지 않음, 자정 넘김 처리, 음수는 "일찍" 표시 |
| 이유(선택) | enum | 취침 기록만 |

| 항목 | 상태 |
| --- | --- |
| 저장 위치 | **미정** (재시작 뒤 기록 유지가 필요함) |
| 외부 의존 | 아이폰 로컬 알림 (**미확인**), 서버·로그인 없음 |
| 차이 계산 기준 | **미정** (권장 구간 7~8시간 중 늦은 쪽을 쓸 예정) |

## 7. 인수 조건 (앱 AC, 전부 `미실행`)

| ID | 시작 상태 | 행동 | 기대 결과 | 확인 방법 | 실제 상태 |
| --- | --- | --- | --- | --- | --- |
| AC1 정상 | 화요일 알람 08:23, 최소 수면 7시간(기준 01:23) | 실제 취침 02:40 입력 | "+77분 늦음" 표시, 목록에 1건 추가 | 표시 값과 목록 수 | 미실행 |
| AC2 자정 경계 | 기준 23:30, 실제 01:10 | 저장 | "+100분" (날짜 넘김 반영) | 계산 결과 | 미실행 |
| AC3 빈 상태 | 화요일 밤(수요일은 알람 없음) | 홈 열기 | 권장 취침 계산 안 함 + 안내 문구 표시 | 홈 화면 | 미실행 |
| AC4 잘못된 입력 | 홈 화면 | 시각 비우고 저장 | 저장 안 됨, 안내 표시, 목록 수 유지 | 안내와 목록 수 | 미실행 |
| AC5 출근 | 토요일 출근 17:00 | 도착 17:03 / 16:58 입력 | "+3분" / "2분 일찍" | 표시 값 | 미실행 |
| AC6 실패 안내 | 아이폰 알림 권한 거부 | 알림 설정 시도 | "알림이 꺼져 있어요" 안내, 기록 기능은 사용 가능 | 안내와 기록 동작 | 미실행 |
| AC7 기록 유지 | 기록 3건 저장 | 앱 종료 후 재실행 | 기록 3건 유지 | 목록 | 미실행 (저장 방식 확인 후) |

**10주차 첫 작업 (제안)**

- 화면: 홈 화면의 "직접 시각 입력"
- 사용자 행동: 실제 취침 시각 입력 → 차이(분) 표시 (메모리 저장, 알림 없음)
- 관련 AC: AC1, AC2, AC4
- 확인 방법: 정상, 자정 경계, 빈 입력을 실행해 결과 확인
- 한계: 앱을 다시 실행하면 기록이 사라지며, 저장(AC7)과 알림(AC6)은 후속 작업
- 후속: 아이폰에서 알림 1건 울리기 작은 확인 작업
