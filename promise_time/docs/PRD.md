# 약속 시각 기록 (가칭) PRD — 제품 요구사항 문서 (현재 v13)

> **상태: 검토안 — 교수님 미확인.** 9주차 초안(`week09/`)을 10주차 양식(6항목)에 맞춰 정리함.
> 아래 숫자(+77분 등)는 **설명용 예시**이며 실제 기록이 아님. 가상 예시의 사실은 쓰지 않음.
> 본인이 아직 확정하지 않은 항목은 `미정` 또는 `제안`으로 표시함.

## 1. 사용자와 사용 상황

- 주제 한 문장: 수업과 주말 알바를 병행하는 대학생이, 정한 시각(취침·출근)과 실제 시각의 차이를 분 단위로 남기고 나아지는지 확인하는 앱
- 첫 사용자: 수업과 주말(토·일) 알바를 병행하는 대학생 (본인)
- 사용하는 순간: 잠자리에 들 때, 주말 알바 출근에 도착했을 때

## 2. 문제·사실·가정

- 문제 한 문장: 요일별 알람이 있어도 정한 시각을 자주 어기지만, 얼마나 어긋나는지 기록이 없어 **나아지고 있는지 알 수 없다.**

| 구분 | 내용 | 근거·한계 또는 확인 방법 |
| --- | --- | --- |
| 확인한 사실 | 밤 2~3시가 넘도록 폰을 보다 자는 날이 많음 (본인은 보상심리 때문이라고 느낌) | 본인 경험, 날짜별 기록 없음. 다른 사람에게 일반화하지 않음 |
| 확인한 사실 | 주말(토·일) 알바 17:00 출근, 16:25 기상 알람(일어나서 바로 씻음), 2~3분 지각이 습관 | 본인 경험, 날짜별 기록 없음 |
| 확인한 사실 | 기상 알람: 월 12:00 / 화·금 08:23·08:25 / 목 09:23·09:25 / 수 없음(공강) / 토·일 16:25 | 본인이 직접 설정한 값 |
| 문제에 관한 가정 | 다른 대학생도 정한 시각을 못 지키지만 얼마나인지는 모를 것 | 미확인 — 추후 확인 예정 (아직 조사하지 않음). 주변 1~2명에게 "지난주 취침·출근 시각을 어떻게 확인했나"를 물어볼 계획 |
| 문제에 관한 가정 | 알바 지각 원인은 알람 후 미룸 또는 준비 시간(35분) 부족 | 미확인. 실제 기상 시각 기록으로 구분 (후속). **이번 첫 화면(기상 기록 없음)으로는 확인할 수 없음** |
| 해결 효과의 가정 | 어긋남을 분 단위로 남기고 쌓으면 나아지는지 알 수 있고, 줄어들 것 | 미확인. 기록이 쌓인 뒤 확인 (저장이 필요함) |

수면 부족과 알바 지각의 **인과는 연결하지 않음** (알바가 17시 출근이라 근거 약함).

## 3. 핵심 가치

- 사용자가 얻을 결과: 밤 시간을 놓치기 싫어 정한 시각을 넘기고 얼마나 넘겼는지도 모른다 → 정한 시각과 실제 시각의 차이를 눈으로 확인하고, 지킨 날을 쌓아 가며 스스로 마무리하는 날이 늘어난다 (**뒷부분은 가정, 미확인.** 장기 변화 확인은 기록 저장 기능이 있어야 가능하며 이번 첫 화면에서는 확인되지 않음)
- 기능과의 연결(핵심 행동): 목표 시각과 실제 시각을 입력해 차이를 확인하고 기록한다
- 계산 자체가 가치는 아니며, **기록이 쌓여 변화를 보여 주는 것**이 가치임. 이번 첫 화면은 그 첫 단계이고, "쌓이는 가치"는 이번 완료 기준으로 검증되지 않음 (저장 없음).

## 4. 기능과 이번 구현 범위

- **앱 비전 (본인 확정, v7)**: "정한 시각에 하루의 약속을 지키도록 돕는 앱."
  - 설명 (제안, 확정 전): 오늘의 약속을 눈에 보이게 하고, 지킨 날을 쌓아 간다. 취침과 알바 출근이 이번 사용 사례이다. "지킨 날을 쌓아 간다"는 앱 전체 비전이며 **이번 구현·검증 범위가 아니다.**
  - 취침 사례의 방향: 밤의 내 시간을 즐기되 정한 시각에 마무리하도록 돕는다 (**미검증 방향**, 현재 기능으로 입증되지 않으며 후속의 남은 시간 표시·늦은 이유 기록이 뒷받침할 후보)
  - "지킨 날"의 기준 (**본인 확정, v7**): 첫 버전에서는 목표 시각에 맞추거나 일찍이면 지킴 (차이 ≤ 0분). **허용 오차는 두지 않음.** 취침·출근 모두 **"늦어도 목표 시각까지"** 로 해석함 (취침도 일찍 자면 지킴). 지킴 판정은 첫 화면에 넣지 않고 후속 범위이며, 판정·연속 기록을 넣을 때는 **날짜 입력이 필요함** (12시간 한계 때문에 12시간 넘게 늦은 경우가 "일찍"으로 계산되어 잘못 "지킴"으로 판정될 수 있음). 연속 기록·장기 누적은 이번 범위에서 **구현·검증하지 않음** (후속)
- **앱 전체의 핵심 기능 후보 (제안)**
  1. 목표 시각과 실제 시각 비교, 차이 계산 (취침·출근 공통)
  2. 기록 저장과 목록, 최근 변화 확인
  3. 취침까지 남은 시간 표시
  4. 수면 7시간 기준 권장 취침 시각 제안
  5. 약속을 지킨 날의 연속 기록
  6. 늦은 이유 기록 (보상심리·습관 등)
  7. 시각 알림, 요일별 설정
- **이번에 구현할 첫 화면과 행동**: 종류(취침/출근) 선택 → 목표 시각 선택 → 실제 시각 선택 → 차이 표시 → "이번 실행 중 기록 목록"에 추가
- 후속 작업과 이유

| 기능 | 이유 |
| --- | --- |
| 기록 저장 | 이번 수업 범위 밖, 새 패키지·방식 미확인. 핵심 가치(변화 확인)에는 필요하므로 **15주차 목표 포함 여부 결정 필요** |
| 남은 시간·권장 취침 제안·연속 기록 | 첫 행동(차이 계산) 확인 뒤 추가 |
| 늦은 이유 기록 | 범위 확대, 후속 |
| 지킴 판정·연속 기록 | **날짜 입력이 먼저 필요함** (시각만으로는 12시간 초과 지각을 판별할 수 없음) |
| 입력 라벨을 "늦어도 몇 시까지?"로 변경 | 규칙을 화면에서도 분명히 하기 위한 후속 개선 후보 (이번 첫 화면 문구는 유지) |
| 알림·요일별 설정 | 아이폰 권한·동작 미확인, 알람이 이미 있는데 지각하므로 우선순위 낮음 |

- 데이터 출처: 사용자 입력만 (시각 선택기). 임시 고정값 없음
- 저장·외부 연동의 현재 범위: **메모리만** (앱을 다시 실행하면 기록이 사라짐), 서버·로그인·알림·추가 패키지 없음

## 5. 첫 화면

규칙
- 종류(취침/출근)는 **목록에서 구분하는 이름표**이며 차이 계산에 영향을 주지 않음
- 종류의 기본값은 **취침** (본인 확정, v7). 항상 하나가 선택된 상태이므로 종류를 고르지 않은 채 기록하는 경우는 발생하지 않음
- 차이(분) = 실제 − 목표를 하루(1440분) 기준 **가장 짧은 방향(−12시간~+12시간)** 으로 계산. 양수는 늦음, 음수는 일찍
- 정확히 12시간 차이는 **+720분(늦게)** 으로 처리
- 결과 문구: 늦음 "N분 늦었어요" / 일찍 "N분 일찍 했어요" / 0분 "목표 시각에 맞췄어요" (종류와 무관하게 동일)
- 목표 또는 실제 시각이 하나라도 비어 있으면 결과를 만들지 않고 목록에 추가하지 않음
- 목록 규칙 (v12): 최신 기록이 맨 앞에 오고, **같은 내용이어도 합치지 않고 각각 한 건**으로 센다. 기록한 뒤에는 값이 바뀌지 않으며, 새 기록이 기존 기록을 바꾸지 않는다. 화면의 건수는 별도 값 없이 **목록 길이에서 바로 표시**한다. 입력 검증은 화면이, 목록 규칙은 목록 관리 클래스가 맡는다. 기록에는 id를 두지 않는다 (수정·삭제가 없어서, 넣는 시점에 검토)
- 한계: 날짜는 입력받지 않고 **입력한 두 시각의 시계상 차이만** 비교하므로, 차이는 최대 ±12시간 범위에서 가장 짧은 방향으로만 계산됨. **실제 오차가 12시간을 넘어도 이를 판별할 수 없고**, 반대 방향의 값으로 표시됨 (예: 목표 01:23, 실제로는 13시간 뒤인 14:23이어도 "660분 일찍"으로 표시)
- 기록 시점은 제한하지 않음 (제안): 시각 선택기로 어느 시각이든 고를 수 있어 그 순간에 입력해도, 나중에 떠올려 입력해도 동작함. 다만 사후 입력은 기억에 의존해 부정확할 수 있는 **자기 보고** 값임. 현재 시각 자동 입력은 후속

| 요구 번호 | 사용자가 볼 정보 | 입력·선택·버튼 | 행동 후 반응 |
| --- | --- | --- | --- |
| R1 | 안내 문구 "오늘 정한 시각과 실제로 한 시각을 선택해 주세요", 종류 선택, "오늘 정한 시각은?" / "실제로 한 시각은?" 두 칸 | 종류 선택, 시각 선택기 2개 | 선택한 값이 칸에 표시됨 |
| R2 | 결과 영역 | "기록" 버튼 | 차이 결과 문구 표시 |
| R3 | **"이번 실행 중 기록 목록 · N건"** 제목 (N은 기록 건수, 처음은 0건), 재실행 시 사라진다는 안내, 기록 한 건: `종류 · 목표 · 실제 · 결과 문구` | 해당 없음 | 기록할 때마다 한 건 추가되고 N이 1 늘어남, 없으면 "아직 기록이 없어요" |
| R4 | 안내 문구 | 해당 없음 | 비어 있으면 "목표 시각과 실제 시각을 모두 입력해 주세요" 표시, 목록 수 유지 |

화면 구상: `docs/first-screen.md` 참고 (한 화면)

빈 데이터·잘못된 입력: 기록 없음, 목표 또는 실제 시각 미선택 (시각 선택기를 쓰면 형식 오류는 발생하지 않음)
