# 5주차 과제 - 상태 기능과 작업 컨텍스트

5주차 상태 기능 구현 및 작업 컨텍스트(Context Packet)를 작성한 저장소입니다.

## 1. 주요 문서
- [CONTEXT_PACKET.md](./CONTEXT_PACKET.md) : 목표, 상태 계약, 데이터 흐름, 프로젝트 컨텍스트 지도 및 인수 조건(AC)
- [PROMPT_COMPARISON.md](./PROMPT_COMPARISON.md) : 동일 요청에 대한 A/B 프롬프트 응답 관찰 및 비교 문서

## 2. 제출 설명

1. **누가 상태를 소유하는가:**
   - `_TaskStatePageState` 클래스가 `_isCompleted` 단일 bool 상태를 소유하고 직접 관리합니다.

2. **AI에게 어떤 자료를 왜 제공했는가:**
   - `CONTEXT_PACKET.md`(목표, 상태 계약, AC 조건)를 제공했습니다.
   - AI가 불필요한 상태 변수를 중복 생성하지 않고 AC4(계산값 별도 저장 금지) 제약 조건을 엄격히 준수하도록 유도하기 위함입니다.

3. **실행 증거가 어느 AC를 확인하는가:**
   - 초기 화면: **AC1** (초기값과 첫 화면 일치)
   - 변경 화면: **AC2** (입력 한 번에 상태와 화면 동시 변경)
   - 원복 화면: **AC3** (역동작으로 값과 화면 원복)
   - `flutter analyze` 결과: **AC7** (코드 품질 및 기능 일치성 검증)

4. **다음 수정에 무엇을 다시 읽어야 하는가:**
   - `CONTEXT_PACKET.md`의 **상태 계약(State Contract)** 섹션과 **인수 조건(AC)**을 다시 읽어, 추후 수정 시 원본 상태와 계산값 분리 원칙이 깨지지 않았는지 재확인해야 합니다.
