# PROMPT_COMPARISON.md - 프롬프트 비교 문서

## 1. 관찰 목적
동일한 기능 구현 요청 시, 작업 맥락(CONTEXT_PACKET)과 제약 조건(AC4: 계산값 중복 저장 금지)을 사전에 제공했을 때와 제공하지 않았을 때 AI 응답의 차이를 관찰하고 비교한다.

## 2. 관찰 결과 비교

| 구분 | 요청 A (맥락 미제공) | 요청 B (CONTEXT_PACKET 제공) |
| :--- | :--- | :--- |
| **프롬프트 입력** | "Flutter에서 버튼 누르면 완료/취소 상태 변경되는 코드 짜줘." | "[CONTEXT_PACKET.md 내용 전달] 이 제약조건과 AC4를 만족하는 Flutter 상태 코드를 작성해줘." |
| **원본 상태 변수** | `bool isCompleted = false;`<br>`String statusText = "진행 중";` | `bool _isCompleted = false;` (단 1개만 사용) |
| **계산값 처리 방식** | `setState` 내에서 `statusText` 변수값을 직접 수정함. | `String get _statusText => ...` 식의 getter로 직접 계산함. |
| **AC4 준수 여부** | **미준수** (계산값을 독립 변수로 중복 저장) | **준수** (원본 상태 1개로만 관리) |

## 3. 결과 분석 및 미확인 항목 구분
- **결과 분석:** 맥락을 제공하지 않은 요청 A는 단순 동작만 맞춰 작성하다 보니 불필요한 상태 변수(`statusText`)를 생성하는 경향을 보였다. 반면 CONTEXT_PACKET을 제공한 요청 B는 AC4 제약 조건을 정확히 인지하여 원본 상태만 변수로 선언하고 나머지는 getter로 처리하는 깨끗한 코드를 출력했다.
- **미확인 항목:** AI 도구 실행 환경의 차이로 인해 서버 비동기 응답 속도 및 다중 화면 전환 환경에서의 상태 유지는 테스트하지 않았음 (본 과제 범위 외).
