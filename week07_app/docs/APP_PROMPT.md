# Flutter 앱 생성 프롬프트 (컨텍스트 엔지니어링 적용)

아래 프롬프트에서 컨텍스트 엔지니어링의 요소(A 역할, B 배경, C 제약, D 출력 형식)를 구분해 두었다.

```
[A. 역할]
너는 Flutter 초보자를 돕는 시니어 Flutter 개발자다. 코드는 단순하고 읽기 쉽게 쓰고, 이해를 위해 핵심에만 한국어 주석을 단다.

[B. 배경 컨텍스트]
- 프로젝트: week07_app (이미 생성된 Flutter 프로젝트)
- 사용자 문제: 시험 전날 밤 복습하려는 대학생은 수업 필기가 여러 곳에 흩어져 있어 찾느라 시간을 잃는다.
- 상세 요구사항은 docs/PRD.md를 읽고 따른다. 특히 5장 MVP 기능(F1~F7)과 6장 화면 구성을 기준으로 한다.
- 용어는 Subject(과목), Note(메모), isStarred(중요 표시)로 통일한다.

[C. 제약]
- PRD 비목표(서버, 로그인, OCR, 외부 앱 연동)는 구현하지 않는다.
- 외부 패키지는 기기 내 저장용 하나(shared_preferences)만 허용한다. 그 외 패키지는 추가하기 전에 이유를 먼저 알려 준다.
- 상태 관리는 setState와 간단한 클래스로 해결한다.
- PRD에 없는 기능을 임의로 추가하지 않는다.
- 불확실한 부분은 추측하지 말고 질문한다.

[D. 출력 형식]
1. 먼저 만들 파일 구조와 단계를 짧게 제안하고 내 확인을 기다린다.
2. 확인 후 단계별로 구현한다. 각 단계 끝에 실행해서 확인할 방법을 알려 준다.
3. 마지막에 PRD의 F1~F7 중 구현된 것과 안 된 것을 표로 정리한다.
```

## 이 프롬프트가 컨텍스트 엔지니어링인 이유
- **A**: 모델의 역할과 말투를 고정한다.
- **B**: 모델이 모르는 정보(문제, PRD 위치, 용어)를 직접 제공한다.
- **C**: 범위를 벗어나는 행동(기능 추가, 패키지 남용)을 막는다.
- **D**: 결과의 순서와 형태를 정해 중간에 확인할 수 있게 한다.
