# PRD: 흩어진 필기 한곳에서 찾기 (가칭)

> 주의: 아래 사용자 경험은 실습용으로 임의로 채운 가상의 예시이며, 실제 조사 결과가 아니다.
> 검증되지 않은 내용은 "가정"으로 표시한다.

## 1. 배경과 문제

- 문제 문장 A: 시험 전날 밤 복습하려는 대학생은 수업 필기가 여러 앱과 사진에 흩어져 있어서, 필요한 내용을 찾느라 복습할 시간을 잃는다.
- 확인한 사실(가상 경험 기준): 필기가 노트 앱, PDF 메모, 캡처 사진, 카톡 "나에게 보내기"에 나뉘어 있었고, 폴더 정리를 시도했지만 미뤄서 실패했다.
- 가정(미검증): 다른 대학생도 같은 문제를 겪는다 / 찾는 시간이 복습에 지장을 줄 만큼 크다 / 사용자는 한곳에 모이길 원한다.

## 2. 목표와 비목표

**목표**
- 과목별로 필기 항목을 한곳에 모아 두고, 시험 전에 빠르게 찾을 수 있게 한다.
- 필기를 남기는 순간의 부담을 최소화한다 (정리를 미루는 문제 완화).

**비목표 (이번 범위 아님)**
- 외부 앱(카톡, 노트 앱) 자동 연동
- 이미지 속 글자 인식(OCR)
- 로그인, 서버 동기화, 여러 기기 공유

## 3. 사용자

| 항목 | 내용 |
|---|---|
| 주 사용자 | 필기를 여러 곳에 남기는 대학생 |
| 핵심 상황 | 수업 중 빠르게 남기기 / 시험 전 복습하며 찾기 |
| 현재 방법 | 앱 여러 개 + 폴더 정리 시도 (자주 실패) |

## 4. 핵심 시나리오 (사용자 스토리)

1. 수업 중: 대학생으로서, 과목을 고르고 메모 한 줄을 몇 초 안에 남기고 싶다.
2. 복습 전: 대학생으로서, 과목을 선택하면 그 과목의 모든 메모를 한 화면에서 보고 싶다.
3. 복습 중: 대학생으로서, 키워드로 모든 과목의 메모를 검색하고 싶다.
4. 복습 중: 대학생으로서, 시험에 중요한 메모에 표시를 해 두고 모아 보고 싶다.

## 5. 기능 범위 (MVP)

| ID | 기능 | 우선순위 | 연결 스토리 |
|---|---|---|---|
| F1 | 과목 추가/목록 | 필수 | 1, 2 |
| F2 | 과목에 메모 빠르게 추가 (텍스트) | 필수 | 1 |
| F3 | 과목별 메모 목록 보기 | 필수 | 2 |
| F4 | 키워드 검색 (전체 과목) | 필수 | 3 |
| F5 | 중요 표시 및 중요 메모만 보기 | 선택 | 4 |
| F6 | 메모 수정/삭제 | 필수 | 1 |
| F7 | 앱을 껐다 켜도 데이터 유지 (기기 내 저장) | 필수 | 전체 |

## 6. 화면 구성

1. **과목 목록 화면**: 과목 카드 목록, 과목 추가 버튼, 상단 검색 진입
2. **메모 목록 화면**: 선택한 과목의 메모 리스트, 중요 필터, 메모 추가 버튼
3. **메모 작성/수정 화면**: 텍스트 입력, 중요 표시 토글, 저장
4. **검색 화면**: 키워드 입력, 과목명이 붙은 결과 리스트

## 7. 비기능 요구

- 메모 추가는 과목 선택 후 3탭 이내로 가능해야 한다.
- 오프라인에서 동작한다.
- 한국어 UI.

## 8. 성공 기준

가정을 검증하기 위한 기준이며 실제 수치는 인터뷰/사용 후 정한다.
- 인터뷰 대상 중 "필기가 2곳 이상에 흩어져 있다"는 응답 비율 확인
- 앱 사용 후 "특정 내용을 찾는 데 걸린 시간"이 이전보다 줄었다는 본인 보고

## 9. 위험과 열린 질문

- 사용자가 사진/PDF 메모를 쓰는데 텍스트만 지원하면 흩어짐이 해결되지 않을 수 있다.
- 정리 미루기가 진짜 원인이라면 검색보다 "빠른 입력"이 핵심일 수 있다. (문장 B와 연결)
- 인터뷰 결과에 따라 범위를 조정한다. 인터뷰 질문은 별도 단계에서 정리했다.

# 부록: 설계 매직 키워드 (DDD 중심)

| 키워드 | 뜻 | 이 앱에 적용 |
|---|---|---|
| 유비쿼터스 언어 | 기획자·개발자가 같은 용어를 쓰기 | 과목(Subject), 메모(Note), 중요 표시(Starred)로 통일 |
| 바운디드 컨텍스트 | 용어와 규칙이 유효한 경계 | 지금은 "필기 보관" 하나만. 일정/과제는 범위 밖 |
| 엔티티 | 식별자로 구분되는 객체 | Subject(id), Note(id) |
| 값 객체 | 값 자체로 의미를 갖는 객체 | 작성 시각, 메모 내용 |
| 애그리거트 | 함께 일관성을 지키는 묶음 | Subject가 Note들을 포함하는 묶음 |
| 리포지토리 | 저장소 접근 추상화 | NoteRepository (기기 내 저장) |
| 유스케이스 | 사용자 목표 단위 동작 | 메모 추가, 과목별 조회, 검색 |
| MVP | 가설 검증용 최소 제품 | 위 5장의 필수 기능만 |
| 사용자 스토리 / 수용 기준 | 가치 중심 요구 + 완료 판단 조건 | 4장 스토리에 수용 기준 추가 가능 |
